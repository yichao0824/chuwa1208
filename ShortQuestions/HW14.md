### Q1 In the CAP theorem, why is Partition Tolerance (P) considered mandatory in a real distributed system? Given that P is mandatory, what is the actual trade-off a system designer must make?
Partition Tolerance (P) is considered mandatory in real distributed systems because network failures, message loss, and communication delays are unavoidable in practice. Since a distributed system must continue to operate even when network partitions occur, P cannot be sacrificed.

Given that partition tolerance is required, the actual trade-off a system designer must make is between Consistency (C) and Availability (A) when a partition happens. A system must either sacrifice availability to maintain strong consistency (CP systems), or sacrifice consistency to remain available (AP systems).
### Q2 Explain the difference between linearizability and eventual consistency. Give one real-world system example for each.
Linearizability guarantees that all operations appear to execute atomically in a single global order, and every read returns the most recent write. A typical example is ZooKeeper, which provides strong consistency for coordination data.

Eventual consistency guarantees that all replicas will converge to the same value if no new updates occur, but reads may temporarily return stale data. A common example is Amazon DynamoDB, which favors availability and scalability over immediate consistency.
### Q3 What is a vector clock? How does it determine whether two events are causally related or concurrent?Why can't we simply use physical timestamps instead?
A vector clock is a logical clock used in distributed systems to capture causal relationships between events. Each process maintains a vector of counters, incrementing its own counter on each event and exchanging vectors when communicating.

To determine causality, event A is causally before event B if all elements of A’s vector clock are less than or equal to those of B, and at least one element is strictly smaller. If neither vector clock is less than or equal to the other, the events are considered concurrent.

Physical timestamps cannot be reliably used because clocks on different machines are not perfectly synchronized and can drift or skew. As a result, physical time may incorrectly order events that are actually concurrent or causally related.
### Q4 In single-leader replication, what is the split-brain problem during failover, and why is it dangerous?
In single-leader replication, the split-brain problem occurs during failover when multiple nodes mistakenly believe they are the leader at the same time, usually due to network partitions or delayed failure detection. As a result, different leaders may accept writes independently.
### Q5 Describe the quorum condition (W + R > N) in leaderless (Dynamo-style) replication. What happens if this condition is not satisfied?
In leaderless (Dynamo-style) replication, the quorum condition W + R > N means that the number of replicas required for a write (W) plus the number required for a read (R) must be greater than the total number of replicas (N). This guarantees that every read overlaps with the latest successful write, allowing the system to return the most recent value.

If this condition is not satisfied, reads and writes may access disjoint sets of replicas, so a read can miss the latest write and return stale or conflicting data. Systems like Amazon DynamoDB accept this risk to improve availability, relying on background reconciliation to eventually converge.
### Q6 Compare Two-Phase Commit (2PC) and the Saga pattern for distributed transactions. What is the main weakness of 2PC that Saga avoids, and what guarantee does Saga sacrifice in return?
Two-Phase Commit (2PC) ensures atomicity by requiring all participants to either commit or abort a transaction together, but it suffers from blocking: if the coordinator fails, participants may remain locked and unable to proceed.

The Saga pattern avoids this blocking problem by breaking a transaction into a sequence of local transactions with compensating actions. However, in doing so, Saga sacrifices strong atomicity, allowing intermediate states to be visible and relying on eventual consistency instead.
### Q7 In the Raft consensus algorithm, why does a candidate need its log to be at least as up-to-date as the majority of the cluster in order to win an election? What safety property does this guarantee?
In Raft, a candidate must have a log that is at least as up-to-date as the majority of the cluster to win an election to ensure that no committed entries are lost. If a candidate with an outdated log were elected, it could overwrite or ignore entries that were already committed by a previous leader.

This requirement guarantees the Leader Completeness safety property: once a log entry is committed, it will appear in the logs of all future leaders, preserving consistency across the cluster.
### Q8 What is a CRDT (Conflict-free Replicated Data Type)? Explain how a G-Counter works and why it always converges without coordination.
A CRDT (Conflict-free Replicated Data Type) is a data structure designed for distributed systems that allows replicas to be updated independently and still converge to the same state without coordination or locking.

A G-Counter (Grow-only Counter) is a CRDT where each replica maintains its own local counter. A replica only increments its own counter, and the global value is computed by summing all replicas’ counters. When replicas exchange states, they merge by taking the maximum value for each replica’s counter, which ensures that increments are never lost.

Because updates are monotonic (only increasing) and the merge operation is commutative, associative, and idempotent, all replicas eventually converge to the same value even in the presence of network delays or partitions.
### Q9 Explain the Circuit Breaker pattern. What are its three states, and how does it prevent cascading failures in a microservices architecture?
The Circuit Breaker pattern is a resilience mechanism used in microservices to prevent repeated calls to a failing service.

It has three states:
1. Closed – requests are allowed to pass through normally.
2. Open – requests are immediately rejected after repeated failures.
3. Half-Open – a limited number of test requests are allowed to check if the service has recovered.

By stopping requests to unhealthy services, the circuit breaker prevents resource exhaustion and avoids cascading failures across dependent services, allowing the system to recover gracefully.
### Q10 What is the difference between range-based partitioning and hash-based partitioning? What problem does consistent hashing solve compared to simple hash-mod-N partitioning?
Range-based partitioning assigns data to partitions based on ordered key ranges, which supports efficient range queries but can suffer from load imbalance if access is skewed.
Hash-based partitioning uses a hash function on the key to distribute data evenly across partitions, but it does not preserve key order and makes range queries inefficient.

Consistent hashing solves the major problem of simple hash-mod-N partitioning: when the number of nodes changes, hash-mod-N causes most keys to be remapped. Consistent hashing minimizes data movement by remapping only a small subset of keys when nodes are added or removed, improving scalability and availability.
